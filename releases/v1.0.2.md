# ThreadScale Release 1.0.2

This version includes:

- a standalone `test_scaling` command for local benchmark-and-report runs;
- valid Mermaid summary charts with measured-point keys;
- effective serial-fraction reporting based on measured speedup;
- expanded local-use and contribution documentation.

ThreadScale 1.0.2 is the next planned release.

<br/>

# Release notes

- Added `./test_scaling`, which runs the same benchmark, matrix, aggregation, and report logic without GitHub
  Actions. It accepts a command template, a command after `--`, or a JSON benchmark file.
- Local runs support the three existing strategies, minimum duration and run-count requirements, warmups,
  per-invocation timeouts, workload rates, and selectable summary plots.
- Fixed GitHub Job Summary chart parse errors by emitting numeric-only Mermaid `line` series. A Markdown key
  below each chart retains the thread count and measured value.
- Added the Amdahl/Karp–Flatt effective serial fraction to aggregate and per-replica summaries, JSON reports,
  and CSV exports. Summary guidance explains that lower values are better and that the estimate includes
  parallel overhead rather than representing a literal percentage of source code.

<br/>

## Documentation

- Added local CLI examples, an annotated Job Summary image, benchmarking guidance, and a contribution guide.
- Clarified that publication-quality measurements should use an otherwise idle machine with stable CPU placement
  and frequency.

<br/>

## Tests

- Added CLI argument-validation and end-to-end local report tests, including sequential thread-sharded
  execution.
- Added regression checks that reject quoted labels inside Mermaid `line` series.
- Added formula, aggregation, summary, and CSV coverage for effective serial-fraction reporting.
- Made CI run names use the triggering commit message or pull-request title.

<br/>

## Compatibility notes

- The local `test_scaling` command requires Node.js 24 or newer, matching the GitHub Action runtime.
- No runtime dependencies or build step were added.

<br/>

## Detailed list of changes and fixes

- Added unique thread labels to partial-result filenames to prevent local sharded runs from overwriting results.
- Reused one detected runner description throughout a local sweep for consistent report metadata.
- Added `test_scaling` as the package's executable entry point while retaining CommonJS and direct Node
  execution.
