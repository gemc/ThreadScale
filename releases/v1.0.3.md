# ThreadScale Release 1.0.3

This version includes:

- a `{workload}` command placeholder that keeps executed work and reported rates synchronized.
- optional workload scaling by requested thread count for throughput-focused measurements.
- explicit comparison groups that place multiple benchmark series and their measured values in one chart.

<br/>

# Release notes

- Command templates can use `{workload}` alongside `{threads}`. ThreadScale replaces it with the benchmark's
  `workload` value for warmups and measured runs, avoiding duplicated workload values in benchmark commands.
- Benchmark definitions can use `comparison_group` and `comparison_label` to render comparable measurements
  as named series in one time or rate chart.
- The `cores-workload-scale` input and `--cores-workload-scale` CLI option increase the one-thread workload by
  a configurable fraction for every additional requested thread. Reports use the actual workload at each point
  and distinguish throughput speedup from fixed-work runtime speedup.
- Restored dots at measured coordinates in summary time, rate, and comparison charts, retaining numeric values
  below each chart.
